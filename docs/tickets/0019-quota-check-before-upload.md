# 19 — Дневная квота проверяется только после полной загрузки файла в S3

GitHub: https://github.com/Kudesnik1506/transcribator_profi/issues/19
Label: `bug`

## What's wrong

Квота (`daily_upload_quota`) проверяется только в `POST /recordings` —
в самом конце flow, после того как весь файл уже отправлен в S3 через
multipart upload (`POST /uploads/multipart` → загрузка частей →
`complete`). Пользователь, исчерпавший лимит, узнаёт об этом только
потратив время и трафик на полную загрузку большого файла, вместо
мгновенного отказа перед стартом.

## Acceptance criteria

- [ ] Квота проверяется до начала multipart-загрузки (на этапе
      создания multipart upload), не только в конце
- [ ] Сообщение об ошибке — то же дружелюбное сообщение с временем
      сброса квоты
- [ ] Двойная проверка в `create_recording` остаётся как защита от
      гонки (TOCTOU между стартом и завершением долгой загрузки)

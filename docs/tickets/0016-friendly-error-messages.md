# 16 — Дружелюбные сообщения об ошибках вместо сырых технических

GitHub: https://github.com/Kudesnik1506/transcribator_profi/issues/16
Label: `bug`

## What's wrong

При недоступном S3 (нет боевых кредов) браузерный e2e-прогон показывает
Пользователю сырые технические сообщения вместо дружелюбных на русском:

- Загрузка файла: `create multipart upload failed: 502`
- Удаление записи в админке: `delete recording failed: 502`

Для сравнения: чат по записи в той же ситуации (недоступен AI Gateway)
корректно показывает «Не удалось получить ответ — сервис ИИ временно
недоступен» — паттерн уже есть в кодовой базе, просто не применён везде.

## Acceptance criteria

- [ ] Ошибки загрузки/удаления показывают дружелюбное сообщение на
      русском, без сырого `<label> failed: <status>`
- [ ] Паттерн приведён к единообразию с уже существующей обработкой
      ошибок чата
- [ ] Технические детали (если нужны) — не в основном тексте для
      Пользователя

## Найдено

Живой браузерный e2e-прогон (Playwright MCP) без реальных S3-кредов,
2026-08-06.

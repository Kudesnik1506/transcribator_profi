# 20 — SpeechKit v3: результат распознавания не получался — неверный контракт getRecognition

GitHub: https://github.com/Kudesnik1506/transcribator_profi/issues/20
Label: `bug`

## What's wrong

Живая проверка с реальными боевыми ключами `YANDEX_API_KEY`/`YANDEX_FOLDER_ID`
(2026-08-09) показала: обработка записи доходила до статуса `done`, но
транскрипт всегда оставался пустым (0 сегментов, сводка не строилась).

Причина — `backend/app/worker/speechkit_client.py` был написан по
документации, недоступной для живой проверки (CAPTCHA), и ошибся в
контракте:

1. Код ждал результат распознавания в поле `response` завершённой
   `Operation`. На практике завершённая операция вообще не содержит
   такого поля — результат нужно отдельно запрашивать через
   `GET /stt/v3/getRecognition?operation_id=...`.
2. `getRecognition` отдаёт поток NDJSON-событий (`final` → опционально
   `finalRefinement` с нормализованным текстом → `eouUpdate`), а не
   единый JSON-объект с полем `chunks`, как предполагал код.
3. Тайминги слов в реальном ответе — `startTimeMs`/`endTimeMs`, уже в
   миллисекундах (`"210"`), а не `startTime`/`endTime` в формате
   `"0.21s"`, который парсил `_time_to_ms`.

Из-за несовпадения структур `result.get("chunks", [])` тихо возвращал
`[]` без единой ошибки — отсюда `done` с пустым транскриптом вместо
явного сбоя.

## Fix

Переписан `speechkit_client.py`: добавлен вызов `getRecognition`, разбор
NDJSON-потока с группировкой событий по `final_index` (предпочтение
`finalRefinement` над сырым `final` при совпадении индекса), тайминги
читаются как целые миллисекунды напрямую.

## Acceptance criteria

- [x] `transcribe()` вызывает `getRecognition` и корректно разбирает
      NDJSON-поток
- [x] `finalRefinement` предпочитается сырому `final` при том же индексе
- [x] Сегменты упорядочены по `final_index`, а не по порядку прихода
      событий
- [x] Тесты покрывают: обычный `final`, предпочтение `finalRefinement`,
      несколько фраз не по порядку, события без слов игнорируются
- [x] Живой прогон с реальными ключами SpeechKit + AI Gateway подтвердил
      корректный транскрипт с таймкодами и построение сводки

## Найдено

Живой прогон через реальный SpeechKit + AI Gateway (боевые ключи
заказчика) — короткий тестовый файл с настоящей русской речью (Windows
SAPI TTS), сырые вызовы API в обход клиента для сверки реального формата
ответа с proto-схемой `yandex/cloud/ai/stt/v3/stt.proto`.

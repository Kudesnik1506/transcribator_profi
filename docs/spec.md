# Транскрибатор — спека

## Context

Заказ с Профи.ру, взят. Веб-приложение для транскрибации аудио и видео: загрузка → извлечение аудиодорожки → распознавание речи с таймкодами → автоматическая краткая сводка → чат по содержанию → история обработок → админка. Заказчик — российское физлицо, разворачиваем на его инфраструктуре, дальше расширяет сам.

Спека получена методом `/grill-with-docs`: интервью по дереву решений, 5 раундов, 27 вопросов. Все ключевые факты (цены, лимиты, WER) проверены по первоисточникам 2026-08-05 и приведены ниже. Фронтир дерева пуст — незакрытых развилок не осталось.

Репозиторий: `github.com/Kudesnik1506/transcribator_profi`, ветка `main`, пустой.

---

## Ключевое ограничение, определившее архитектуру

Заказчик — **физлицо в РФ**. Это отсекает почти весь рынок ASR:

| Провайдер | Статус |
|---|---|
| **Яндекс SpeechKit** | **доступен** — личный платёжный аккаунт, оплата картой или СБП |
| Sber SaluteSpeech | **закрыт для новых клиентов с 15.07.2026** |
| T-Bank VoiceKit | **только ИП и юрлица** с договором |
| OpenAI / Anthropic напрямую | недоступны из РФ |

SpeechKit остаётся единственным облачным ASR с пословными таймкодами, доступным заказчику. Выбор вынужденный — поэтому провайдер прячется за интерфейсом, чтобы уход на self-hosted не означал переписывания приложения.

## Стек

**Бэкенд** FastAPI + PostgreSQL + Redis (очередь ARQ) · **Фронтенд** Next.js + React + Tailwind · **Воркер** Python + ffmpeg · **Хранилище** Timeweb S3 · **Хостинг** Timeweb Cloud, Москва
**ASR** Яндекс SpeechKit, асинхронный режим · **LLM** Timeweb AI Gateway (OpenAI-совместимый) · **Почта** SMTP заказчика · **Уведомления** Email + Telegram-бот

---

## Глоссарий (→ `CONTEXT.md`)

- **Запись** (Recording) — то, что загрузил пользователь, вместе с исходным медиафайлом. _Avoid_: файл, обработка, материал
- **Транскрипт** — полный текст Записи с таймкодами. _Avoid_: транскрипция, расшифровка
- **Сегмент** — единица Транскрипта: `{ start, end, text, speaker }`. `speaker` в MVP всегда пустой
- **Кусок** (Chunk) — фрагмент аудио 10–15 минут, единица распознавания и ретрая. Внутренний термин, пользователю не показывается
- **Сводка** — краткое содержание Транскрипта, 5–15 пунктов
- **Диалог** — история вопросов и ответов по одной Записи. _Avoid_: чат, сессия
- **Обработка** — **не сущность, а статус Записи** в конвейере

## Decisions Log

| ID | Тема | Решение | Обоснование |
|---|---|---|---|
| D1 | Хостинг | Timeweb Cloud, Москва | Заказчик российский, записи содержат ПДн, трансграничка — риск |
| D2 | Язык | Только русский, автоопределение не обещаем | Ответ заказчика |
| D3 | Нагрузка | До 3 ч и ~2 ГБ на файл, 15 файлов/день, 5 пользователей | Ответ заказчика |
| D4 | Биллинг ИИ | Ключи и оплата на стороне заказчика | Иначе бессрочный операционный расход внутри фиксированной цены |
| D5 | Доступ | Регистрация + ручное одобрение админом, 3 файла/день на пользователя | Открытая регистрация = неконтролируемый расход на ИИ и чужой контент на сервере заказчика |
| D6 | Ретеншн | Медиа 30 дней, Транскрипт + Сводка + Диалог 180 дней. Обе цифры в конфиге | Медиа при 180 днях даёт 2–4 ТБ и заметный счёт; текст стоит копейки |
| D7 | Диаризация | Не в MVP. Поле `speaker` в схеме заложено. Этап 2 | SpeechKit умеет максимум 2 диктора и только моно — для совещаний бесполезно. Полноценная диаризация требует GPU |
| D8 | Хранилище | Timeweb S3 | Следствие D10 |
| D9 | ASR | SpeechKit асинхронный, провайдер за интерфейсом. Параллельно запрос КП на GPU у Timeweb; при выгодных цифрах — GigaAM v3 на этапе 2 | Единственный доступный физлицу облачный ASR с таймкодами. Whisper отклонён: WER на русском 16–21 % против 8–9 % у GigaAM. Если self-hosted — то GigaAM (MIT), не Whisper |
| D10 | Загрузка | Прямо в S3 по пресайн-ссылке, multipart-частями | Честный прогресс, докачка после обрыва, ноль трафика через VPS |
| D11 | Подача в ASR | Аудио телом запроса в OggOpus, второй бакет у Яндекса не заводим | 15 минут в OggOpus ≈ 2,7 МБ при лимите 60 МБ |
| D12 | Сбои | Нарезка на куски 10–15 мин, свой ретрай на кусок (3 попытки с backoff), статус «Частично обработана», честный процент | Потерять три часа обработки и оплату за неё из-за одного сбойного куска недопустимо |
| D13 | LLM | Timeweb AI Gateway | OpenAI-совместимый API, тот же кабинет и счёт, что и хостинг; смена модели — одна строка в `.env` |
| D14 | Чат | Полный Транскрипт в каждый запрос. RAG и векторной БД в MVP нет | 3 часа ≈ 80k токенов, влезает в 128k. RAG ломает ровно те вопросы, что приведены примерами в ТЗ: «о чём говорилось в начале», «перечисли всех упомянутых» |
| D15 | Режим обработки | Выбор пользователя при загрузке: «сейчас» (~30 мин) или «в фоне, дешевле» (до 24 ч). Дефолт — фоновый | Отложенный тариф SpeechKit вчетверо дешевле обычного. Управление расходом отдаём тому, кто платит; на приёмке демо жмёт «сейчас». Цифры — в `docs/economics.local.md` |
| D16 | Таймкоды в UI | Плеер + клик по абзацу перематывает, текущий абзац подсвечен | Таймкоды без перехода к моменту — полумера |
| D17 | Уведомления | Email обязательно, Telegram-бот опционально по привязке | При ожидании до суток статус в интерфейсе не работает — человек не вернётся |
| D18 | Порядок работ | Сквозной скелет первым, дальше наращивание | Риски интеграции со SpeechKit вскрываются на первой неделе, а не на последней |
| D19 | Экспорт | `.txt`, `.srt`, `.docx`. PDF не делаем | При готовых таймкодах это несколько строк кода; вёрстка PDF съест время без ценности |
| D20 | Поиск | PostgreSQL full-text search по сегментам, конфигурация `russian` | Ищем по всей Записи, а не по видимой части страницы |
| D21 | Админка | Минимальная: пользователи, все Записи, удаление, логи ошибок | Четыре страницы поверх существующих запросов. Закрывает все пункты ТЗ и снимает риск спора на приёмке |

## Экономика

Себестоимость обработки, оценка месячного расхода заказчика и трудозатраты вынесены в `docs/economics.local.md` — файл под `.gitignore` и в репозиторий не попадает.

Что из этого влияет на архитектуру и потому остаётся здесь: **распознавание — доминирующая статья расхода**, и два тарифа SpeechKit отличаются вчетверо при разнице в задержке от получаса до суток. Отсюда решение D15 — выбор режима отдан пользователю в интерфейс.

## Схема данных

```
users          id, email, password_hash, role(user|admin),
               status(pending|active|blocked), telegram_chat_id, created_at

recordings     id, user_id, original_filename, s3_key_media, s3_key_audio,
               duration_sec, size_bytes, mode(fast|deferred),
               status, progress_percent, error_message,
               created_at, media_deleted_at

chunks         id, recording_id, idx, start_sec, end_sec,
               status, attempts, asr_operation_id

segments       id, recording_id, chunk_id, start_ms, end_ms,
               text, speaker NULL, tsv tsvector

summaries      id, recording_id, items jsonb, model, created_at

messages       id, recording_id, role(user|assistant), content, created_at

error_logs     id, recording_id NULL, level, message, context jsonb, created_at
```

Статусы Записи: `uploading → queued → extracting → transcribing → summarizing → done` · `partial` · `failed`
GIN-индекс на `segments.tsv`, заполняется триггером с `to_tsvector('russian', text)`.
Таймкоды сегмента хранятся **абсолютными от начала Записи** — смещение куска прибавляется при сохранении, чтобы плеер и SRT не требовали пересчёта.

## Конвейер обработки

1. Фронтенд запрашивает пресайн-ссылки на multipart-загрузку → браузер грузит файл **напрямую в Timeweb S3**, минуя бэкенд
2. По завершении — `POST /recordings` с ключом S3, именем файла и режимом → задача в очередь Redis
3. Воркер скачивает медиа из S3
4. `ffmpeg -vn -sn -dn -map 0:a:0 -ac 1 -ar 16000 -acodec libopus -b:a 24k` → моно OggOpus
5. Нарезка на куски по 15 минут (~2,7 МБ каждый)
6. По каждому куску: отправка в SpeechKit асинхронно **телом запроса**, опрос операции, сохранение сегментов со смещением таймкодов. Ретрай 3 раза с нарастающей паузой
7. Все куски готовы → сборка Транскрипта → Сводка через Timeweb AI Gateway → `done`
8. Часть кусков не поднялась после ретраев → `partial`, пользователь видит что есть и может допровести неудавшиеся
9. Уведомление на email, при привязке — в Telegram

Ночной cron: удаление медиа старше `MEDIA_RETENTION_DAYS` (30), удаление Записей целиком старше `DATA_RETENTION_DAYS` (180). Квота 3 загрузки в календарные сутки МСК на пользователя.

## Экраны

**Пользователь** — вход · регистрация с экраном «ожидает одобрения» · загрузка (drag-n-drop, прогресс по частям, выбор режима) · список Записей (имя, дата, статус, процент) · страница результата: плеер + Транскрипт с таймкодами и подсветкой + Сводка + Диалог + поиск + кнопки экспорта

## Развёртывание

`docker-compose.yml` — локальная разработка: `web` (Next.js dev-сервер) · `api` (FastAPI) · `worker` (Python + ffmpeg) · `postgres` · `redis`, порты пробрасываются на хост напрямую, TLS не нужен.

`docker-compose.prod.yml` (тикет #15) — прод, отдельный файл вместо режима сверху: те же сервисы плюс `caddy` (TLS, автоматические сертификаты Let's Encrypt), `web` собирается из прод-сборки Next.js (`web/Dockerfile.prod`), ни один сервис кроме `caddy` не публикует порты наружу. Решение оставить два файла, а не расширять один и тот же `docker-compose.yml` режимом для прода — чтобы не переусложнять локальную разработку TLS/доменами, которые ей не нужны.

`.env.example` со всеми ключами: доступы к Timeweb S3, `YANDEX_API_KEY` + `YANDEX_FOLDER_ID`, `TIMEWEB_AI_GATEWAY_KEY` + модель, SMTP, `TELEGRAM_BOT_TOKEN`, обе цифры ретеншна, дневная квота.

`README.md` — запуск одной командой, получение каждого ключа по шагам, восстановление из бэкапа, как поменять модель LLM, как переключить режим ASR.

## Проверка

- **Сквозной прогон**: реальный 3-часовой mp4 → появились Транскрипт, Сводка и Диалог; таймкоды в плеере совпадают со звуком; поиск находит слово из середины записи
- **Сбой куска**: заглушкой валим 3-й кусок → Запись получает `partial`, остальные 11 сохранены, повтор доводит до `done`
- **Обрыв загрузки**: рвём сеть на 60 % загрузки 2-гигабайтного файла → докачка продолжает с места
- **Оба режима**: «сейчас» и «в фоне» дают одинаковый Транскрипт, письмо и сообщение в Telegram приходят
- **Квота**: четвёртая загрузка за сутки отклоняется с внятным сообщением
- **Модерация**: новый пользователь не может войти до одобрения админом
- **Ретеншн**: прогон джобы на подкрученных датах удаляет медиа и оставляет текст; на 181-й день удаляет всё, включая объекты в S3
- **Экспорт**: `.srt` открывается плеером и попадает в такт, `.docx` открывается в Word
- **Развёртывание с нуля**: чистая машина, `git clone` + `.env` + `docker compose up` по README без вопросов к автору

## Вопросы к заказчику (не блокируют разработку)

1. Реквизиты SMTP-ящика для писем
2. Аккаунт Yandex Cloud и Timeweb AI Gateway — завести и передать ключи
3. Подтвердить ретеншн: медиа 30 дней, тексты 180 дней
4. Показать верхнюю оценку месячного расхода на ИИ до старта, чтобы счёт не стал сюрпризом
5. Диаризация спикеров и self-hosted GigaAM — этап 2, отдельное КП

**Открытый пункт приёмки (тикет #15):** «Отладка на реальных трёхчасовых записях» (оба режима, сбой Куска, обрыв загрузки) требует реальных ключей SpeechKit и AI Gateway (вопрос #2 выше) — без них выполнена только структурная проверка: устойчивость к сбою Куска и докачка после обрыва покрыты автотестами и живым прогоном с заглушками S3/SpeechKit/AI Gateway (см. коммиты по тикетам #1–#14), но ни разу не прогонялись на настоящем трёхчасовом файле через реальный SpeechKit. Это надо сделать первым делом после получения ключей — контракт SpeechKit v3 реконструирован по документации, доступной частично (см. docstring в `backend/app/worker/speechkit_client.py`), и не проверялся вживую.

# Чат на полном контексте вместо RAG

В каждый запрос к языковой модели уходит **весь Транскрипт целиком**, вместе с историей Диалога. Векторной базы, эмбеддингов и поиска по фрагментам в системе нет.

Транскрипт трёхчасовой записи — около 80 тысяч токенов, а доступные модели через Timeweb AI Gateway дают 128 тысяч и больше. Полный контекст влезает с запасом, а стоит один прогон около 5,5 ₽ — то есть RAG экономил бы копейки ценой заметного усложнения.

Решающий довод не в цене, а в качестве. RAG ломается ровно на тех вопросах, которые заказчик привёл примерами в техническом задании: «о чём говорилось в начале», «перечисли всех упомянутых людей». Оба требуют видеть запись целиком, а не релевантные фрагменты. Реализация, которая не отвечает на примеры из ТЗ, не считается работающей.

## Consequences

- Никакой векторной БД в стеке — меньше кода, меньше движущихся частей, проще инструкция по запуску
- Потолок: записи длиннее примерно четырёх с половиной часов в контекст не поместятся. При текущем ограничении в 3 часа это недостижимо; если ограничение поднимут, вопрос придётся открыть заново
- Смена модели — одна строка в `.env`, так как шлюз OpenAI-совместимый; при смене обязательно проверять размер контекстного окна новой модели
